## 점검 후 실행 순서

1. 17시 이후 실제 서버 점검 종료 및 현재 앱 화면 확인. 연장 중에는 입력/로그인 반복 금지.
2. 의뢰 최신 이름 분류/동일성 수정의 신규 출항, 연구 누적 수령/대기열 확인.
   10:49 이전 성공과 최신 코드 실기를 혼동하지 않는다.
3. **대형작전 일일·좌표·요새·보스의 개별 기능**을 우선 확인한다. 개척만 반복하며
   이들을 모두 개척 완료 대기로 두지 않는다. `is_in_opsi_explore()`는 게임 해금이
   아니라 Enable/NextRun 기반 스케줄 조건이다. 독립 검증 동안 필요하면 Alas.exe
   UI로 개척을 일시 비활성화하되 LastZone=72와 실제 진행을 바꾸지 않고, 종료 후
   활성 상태를 복원한다. 이것을 개척 완료로 기록하지 않는다.
4. AP/좌표/적응도/현재 함대 조건을 먼저 확인한다. AP 구매 상한1은 유지하고
   추가 유료 구매나 보호 제한 완화는 하지 않는다. 한 작업이 조건 부족이면
   실제 원인을 기록하고 다른 독립 작업을 확인한다. ForceRun을 무작정 켜지 않는다.
5. SP는 원래 편성 복원 정보가 오면 검증한다. 정보 없이 다른 함대를 임의로
   구성하거나 기존 제1함대가 원복됐다고 추정하지 않는다.
6. 20시 보고는 `실기 확인`, `수정/오프라인만 확인`, `조건 미충족`, `유료/범위 제외`를
   구분한다. 메뉴 전체나 모든 이벤트/상품/상황을 검증했다는 백분율을 만들지 않는다.

## 오프라인 감사에서 확인한 대형작전 제약

- `module/os/tasks/explore.py`는 개척 중 다른 OS 작업 예약을 뒤로 미룬다.
- `module/os_handler/mission.py:is_in_opsi_explore`는 스케줄 상태 판정이다.
- `archive.py`, `month_boss.py`, `meowfficer_farming.py`는 이 상태에 따라 조기 종료한다.
- `daily.py`는 개척 중 항구 임무 경로가 달라진다. `obscure.py`의 ForceRun=false는
  한 좌표 처리 후 반환하지만 abyssal/stronghold는 반복하면서 작업 전환을 검사한다.
- `module/campaign/os_run.py`는 AP 부족 예외를 예약 연기로 처리한다. 이 경우의
  End task 로그는 전투 성공 근거가 아니다. 월간 보스 적응도 검사는 유지한다.

## 11:00 종료 경계 오프라인 검사

`dev_tools/test_os_task_stop_boundaries.py`에서 실제 운영 함수 본문을 장치 없는
모의 객체로 실행했다. 좌표 없음/요새 없음은 임의 해역 진입 전에 중단하고,
심연 전투 실패는 성공 후처리로 넘어가지 않는다. 일반 좌표 ForceRun=false는
한 좌표 후 반환하며, 심연/요새 반복은 해역 사이의 스케줄러 중지를 따른다.
OS 래퍼 9종에서 초기화 중 및 작업 중 AP 부족 예외 모두 재시도 없이 예약 연기로
전달됐다. 새 검사 7개와 AP OCR/항구 수리/해역 종류/S결과 검사를 함께 실행해
22개 통과했다. 운영 코드를 변경하거나 게임을 실행하지 않았다.
이는 이미지 인식·좌표 사용·실제 전투·실제 구매 성공의 증거가 아니다.

## 11:03 한글 UI 문구 구조 감사

- `unittest discover -s dev_tools -p test_*.py`로 기존 33개 검사 파일의
  140개 오프라인 검사를 모두 실행해 통과했다. 선택 명령에서 누락된 파일은 없었다.
- 영어/한국어 로캘 각각 1,714개 말단 문구를 대조했다. 키 누락 0,
  영어에 내용이 있는데 한국어가 빈 항목 0, 중괄호 치환 변수 불일치 0이다.
  빈 문구 206개는 영어도 비어 있는 도움말 등을 포함하므로 번역 누락 수가 아니다.
- 동일한 검사를 `test_kr_locale_integrity.py`에 추가했고 중복 JSON 키도 거부한다.
  새 검사 3개 통과. 이는 번역 정확도/전체 UI 배치/실제 렌더링을 검증하지 않는다.
- 영문과 같은 문자열 중 ALAS·에뮬레이터 백엔드·패키지명은 그대로 유지할
  기술 식별자다. 그러나 Campaign.Event의 다수 이벤트/작전문서 제목도 영문으로
  남아 있으므로 **전체 한글화 완료가 아니다**. 한국 서버 공식 명칭의 근거 없이
  임의 제목을 공식 번역처럼 덮어쓰지 않는다. 이 제목 대응은 별도 남은 작업이다.

## 11:08 이미지 선택/파일 경계 감사

- `module/base/resource.py`는 KR 명시 값이 있으면 이를 우선하고, 없으면
  `SERVER_ASSET_FALLBACK['kr']='jp'`를 사용한다. 일본어 값까지 없을 때
  임의로 다른 서버를 고르지 않는 경로와 전역 서버/공유 값 선택을 5개 검사로 확인했다.
- 기존 검사는 KR 파일/영역이 모두 명시된 Button만 검사했다. 이를 보완해
  실제 KR 해석 결과와 JP fallback까지 파일 존재 및 영역 경계를 검사했다.
  `module/**/assets.py`의 정적 Button 정의 1,245개가 대상이며 KR 명시 정의는
  155개였다. 모두 파일을 읽을 수 있고 인식 영역이 이미지 크기 이내였다.
- 이는 Template 클래스·동적 Button 전부의 검사도, 현재 게임 화면의 일치율도
  아니다. 특히 fallback 이미지가 한국어 화면에 맞는다고 입증하지 않는다.
  실제 대형작전 좌표/요새/보스 화면의 한국어 차이는 점검 후 확인해야 한다.
- 전체 오프라인 검사 150개 통과. 실행 중인 게임 작업은 없으며 운영 코드나
  이미지 선택 정책을 이번 감사에서 변경하지 않았다.
